# GaussDB DDL 与分布策略

先核对实际 GaussDB 版本及表类型支持，再决定 HASH 或 REPLICATION。不能默认第一列作为分布键。

HASH 候选键应在大表中有足够基数、空值率低、值分布较均衡，并尽量与高频大表 JOIN 键一致。用样本统计频数和节点数据量检验倾斜。小维表可考虑 REPLICATION，但需确认表大小、更新频率和集群能力。列存适合扫描/聚合，行存适合高频点查或更新；不要只按层级判断。

配置明确给出策略时生成对应 DDL。缺少数据量、基数或查询模式时保留 NEED_CONFIRM 并禁用发布。检查 HASH 键确实存在于表字段、不是常量或低基数字段；检查复制表大小与更新代价。
